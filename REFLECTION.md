The part that I repeated by hand the most was the shared page structure. Every page uses the same header, nav, footer, stylesheet links, logo link, and current page navigation state. The family pages were also repetitive because `fresh.html`, `soft.html`, `blue.html`, and `hard.html` all use the same structure with different text, image paths, active navigation links, and previous/next links. I also repeated small form patterns, like the fieldset, labels, inputs, and submit button.

The easiest thing to break was file paths. Once I moved into the `guide/` folder, every shared asset needed a different relative path. On the root level pages, styles are linked as `styles/site.css` and images as `images/logo.svg`. Inside `guide/`, those become `../styles/site.css` and `../images/logo.svg`. Although it's a small change, it affects every stylesheet, image, and navigation link. If one path is wrong, the page can look completely unstyled or an image can disappear. The current page navigation state was also another easy thing to miss because every page needs a different `aria-current="page"`.

I would want a tool to generate the repeated page shell for me: document head, shared header, nav, footer, and correct relative paths based on where the file lives. For the family pages, I would want to define the cheese data once, maybe as a structured content, and have the pages generated from a template. The tool could automatically create the previous/next links, active navigation state, titles, descriptions, image classes, and view-transition names.

This homework made me realize the value of web components and static site generators. I don't need a framework to write a small static site, but I also want a reliable way to reuse shared layout and content patterns without copy pasting the same components by hand.
